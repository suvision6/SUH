# 修订、精确输入与交接

## 精确镜头输入

作为本轮输入的已有分镜，其实际镜头、景别、关键机位、调度、动作时点与声画/Cut关系默认保留，无需用户另说锁定；明确修改授权只作用于对应范围。原号继续用于定位，不从新场级段落伪造上游镜号。需要精确稿时，可直接交保留原结构的可读 Markdown；兼容指理解和忠实修订，不意味着本包包含旧导出器。

一镜仍指连续画面，已有实际镜头及其切点默认继承，连续长镜不能因技术分段被拆成成片Cut。段落、分镜行、节拍或Image9格并非天然的镜头边界；按实际声画判断，不机械一行一Cut。没有源镜号时，仍按正文已给出的连续观看与真实切换继承，并核对事件、对白和关键观看覆盖。

缺少实际源文件时说明只根据用户提供的内容处理，不能声称核对了文件。未提供的精确时长不要填 0。局部修订实质改变发言/行动/先后才重估相关占时；澄清表达不自动重算全场或统一改速率。

## 台词修订与未决问题

实际修订与局部未决按 [Workflow第1步](Workflow.md#1-建立本轮有效输入)及第9步执行；本节说明台词疑点的边界。

例如来源写“别在问了”，即使判断可能想写“别再问了”，采用正文仍保留原字；将疑点放在局部未决，并等待确认。正文不得先用猜测的正确字，再在备注里说待核。用户随后明确采用改字，才以新句核对。无关部分继续完成，不让一处歧义变成整稿停工。

## 交给 Prompt 或 Image9

完整接口与保存按 [Workflow第8步](Workflow.md#8-保存成果让下一位能接着做)。同一 Agent 连续承担导演与 Prompt 也保留职责边界，执行选择不能静默反写剧情。

Prompt 准确展开已有分镜及其实际镜头关系，在实际入口与素材条件下组织生成请求和明确开放的微调，并核对当次实际对白片段和必须完成过程的容纳性。导演稿不设置统一 15/30 秒容器，生成请求分组不增、删或合并已有成片Cut。若执行范围确实容纳不下，反馈受影响内容和候选办法，其他独立范围继续，不先提速删词或擅改关键节点。

Image9 可对本次指定空间、调度或镜头关系做快速静态检查，带必要前后状态并回传相关反馈；也可从剧本、场级稿或精确稿组织请求范围的完整叙事静帧预演，在未锁定部分设计候选摄影、镜头与组接。按请求区分范围，不把快检扩成整场全套，也不循环要求本 Skill 先写完精确分镜。每次预演物料由用户确认，Skill间可人工衔接；Image9可完全跳过。

采用预演成果要落实到实际范围：接受布局只约束布局，接受整套候选镜头序列才继承相应拍法；与原锁定冲突的部分需要明确改变该锁定的选择。一格不是一 Cut，采用一图不自动指定首帧/尾帧。未采用方案、标注和图像偶然细节不成为正式剧情依据。

## 真实结果与修改范围

局部修改的执行顺序、完整替换稿与依赖回查集中在 [Workflow第9步](Workflow.md#9-出现问题时回到有责任的步骤)。本节用于判断证据能支持什么修订。

按任务授权可以读取实际图片/视频/音频。先描述证据，再对照来源与当前采用稿，不把最近一张错图当新的初态，也不假称下段已能继承正确状态。

| 证据与问题 | 处理 |
|---|---|
| 来源缺少必要事实或台词修订对应不清 | 定位局部待确认；其他可做部分继续 |
| 导演稿漏关键观看、空间矛盾或时长不成立 | 认定设计问题并提出受影响范围的修订 |
| 导演稿明确，但 Prompt 漏条件或擅改自由度 | 指出表达/组织问题，不反过来放松原稿 |
| 实际结果违背清楚无矛盾的输入 | 记录该次未执行，并提出修复建议；不能据此改事实 |
| 只有截图或部分片段 | 只判断可见部分，不认证未显示的动作、声位或时长 |

改变已采用关键节点的建议保持待采用地位；明确修改授权只作用于对应范围。

文本核对只证明字面与所选数值。Agent 回读不是人工审片；静帧不能证明连续路径、真实速度、口型或剪辑节奏。无实际媒体时报告设计完成及未验证部分。本版本不自动提交生图、视频、生成式编辑、延长、重试，也不自动把反馈写成新 Skill 规则。
