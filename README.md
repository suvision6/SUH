## 使用入口

每个 `skills/<名称>/` 是一个完整的运行目录。使用时明确指定上表中的名称，并读取该目录的 `SKILL.md` 及任务所需参考。目录名和正式调用名保持原样；SUH 与旧 `su-*` 系列分开。

分镜、Image9、Prompt 的现有策略为仅显式调用；美术保留其原有策略。四个入口独立，不存在名为 `suh-workflow` 的第五个自动总控。不要把名称相似当作规则可混用的依据。

新的创作物料按各包规则交用户确认；仅安装、读取、准备文字或维护Skill不构成媒体生成授权。本仓库的脚本用于本地文本交付、状态及媒体登记、校验和排版，不包含媒体provider凭据或生成SDK。实际图像操作依具体授权及宿主提供的工具。

## 文件范围

本仓库保留四包运行所需的入口、版本、界面配置、参考文档、模板、本地脚本、被引用的教学示例及许可/归属文件。选入文件与对应已验证安装来源逐字节一致，清单见 [MANIFEST.json](MANIFEST.json)。原有候选版本标签保持，不把发布到GitHub等同于艺术或生产能力认证。

`examples/` 中的内容是Skill说明引用的教学源文件，不是用户真实项目输出。Image9的 `VALIDATION.md` 因被来源说明引用而保留，用于说明历史检查范围；具体运行日志和回归产物不在本仓库。

不包含：本机API凭据、Token、Key、账号配置、安装备份、历史候选工程、测试执行记录、回归输出、导出工作区、图片、视频、音频、PDF、Excel或其他用户创作物料。未被引用的历史变更日志及独立测试夹具留在本地。

## 本地工具与依赖

按照各包工具说明选择已有运行环境，不自动安装依赖。文字交付器主要使用Python标准库；Image9的图片解码/登记需要Pillow，PDF排版另需ReportLab及本地可嵌入字体。可选Excel交付按对应说明使用已有Node与所需库。
