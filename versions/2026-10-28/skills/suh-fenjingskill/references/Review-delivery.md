# 同源载体比较与人类反馈回流

审阅载体服务专业工作及Agent协作。当前提供可运行的Markdown、Excel和固定HTML对照；**尚未锁定默认审阅载体**，不意味着各职责的正文规范未定。不要每次无条件导出三套。根据任务明确选择；载体会影响本次主要审阅方式而未定时，只问一次具体选择。普通文本任务可先交完整可读主稿，不因等待文件选型停下导演工作。

## 同一内容派生

Agent在专业稿完成后整理现有`suh-delivery/1`快照，不让用户填写JSON。`deliver.prepare()`是同文入口，实际对白由有效ledger展开。`body`是本单元完整正文，`copy_text`只在允许的种类中作独立绘图输入；Prompt正文仍是唯一执行文本。审阅工具不另写来源/正文，也不自动摘要、导演或判断质量。

```text
python3 scripts/review_delivery.py export <Bundle.json> --out <新审阅目录>
python3 scripts/review_delivery.py export <Bundle.json> --out <另一个新目录> --xlsx --node <现有Node绝对路径> --node-modules <现有依赖目录> --render
```

第一条只生成Markdown、HTML及基线；第二条增加Excel，可选渲染三个工作表的代表范围。当前Excel适配器使用已有`@oai/artifact-tool`，从宿主依赖工具获取路径；缺失就明确报告，不安装或猜环境路径。HTML/Markdown及回流读取只需Python标准库。文件写后回读；既有目录拒绝覆盖。导出器只检验声明的内容，不认证原稿完整、真人身份或采用。

Excel主表的单元ID/来源ID、估时说明、完整正文和专用意见列同源输出；长文按同单元的稳定片段ID续行，重拼逐字相等，估时只在首行。续行不是新镜头/新生成段，排序不改变创作顺序。来源原文独立只读视图；极长来源同样续行。未知时间保留“未提供”，不计成0秒。不得为表格改写创作粒度。

HTML用固定本地模板，来源可展开、正文可编辑、意见另列；明确“导出反馈JSON”才能保存本页改动，关闭页面前须确认下载成功。没有云服务或localStorage采用状态。直接改网页只是候选反馈，不修改主稿；复制按钮复制当前正文，不能把评论混入。HTML原文字面转义，原文中的标签不执行。

## 反馈先提取，不自动采用

```text
python3 scripts/review_delivery.py import-feedback <原Bundle.json> <已修改Review.xlsx或Review-feedback.json> --out <新的候选Patch.json>
```

Agent必须提供导出时的同一Bundle。脚本校验基线摘要、完整单元/片段ID，排序允许，重复/缺失/未知ID拒绝；删除行不推断成删除剧情。来源/估时被直接改动则停该导入，保留文件并从具体意见进行专业修订，不丢掉反馈。正文差异与意见分别提取，哪怕意见写“通过”，也不会成为批准记录。

支持：专用意见列；Review表正文/意见单元格的传统Excel Notes（旧式批注）提取为意见。**不支持现代 threaded Comments/replies**；检测到即拒绝并报告，保留原文件，Agent应显式读取或请用户导出相应文字，不能静默漏掉。其他表/列的Notes同样明确拦截。尚未在Mac Excel/WPS各版本中验证所有注释保真；不宣称全类型批注回流。

## 只应用明确范围的正文修改

Agent读候选差异、实际用户原话与当前上下文，判断直接改词、建议、否决或采用的区别。明确修改范围无需重复询问；有实质矛盾只问对应内容。先更新对应专业正文及有效对白ledger，形成新Bundle，再用工具核对实际结果是否仅包含选定字面修改：

```text
python3 scripts/review_delivery.py apply-feedback <原Bundle.json> <Patch.json> --candidate <已复核新Bundle.json> --accept S01 S03 --evidence-ref <本次真实反馈定位> --evidence-text <真实原话> --out <新的应用目录>
```

工具不从自由意见自动写正文。新候选须精确等于被接受的正文修改；未选单元、来源、时间、依赖、采用维度等不得借机变化。台词改动必须重整对应ledger，按原字展开回查；不通过全局替换猜哪句要改。需要影响相邻时间/状态或人类建议不是直接改稿时，走专业修订并记录真实依赖，不能硬塞进字面应用器以假通过。

应用只产出新候选，保留原稿；随后回查先后、时间和状态，并按[交接与采用规则](Handoff.md)处理采用。新Bundle用新的artifact ID注册，应用报告不是人类批准。真实用户明确“改完继续”按其条件执行；只有修改要求则交修改稿等待审阅。

预演body改动会在返回候选中标记derivation_pending及当前正文摘要，提醒同步页copy_text与受影响格current_input；字面应用器仍不允许借机修改这些派生字段。Agent另做范围明确的专业修订；使用媒体台账时按Media-execution的派生协调处理，纯标点/无静格影响可确认无需改绘图输入。标记不是要求重新生成图片或再次人审。

## 本轮对照能证明什么

同源样稿能比较可读性、反馈入口、字面回读、稳定ID和运行成本。固定HTML不需要模型每次重新写页面；Excel也由固定程序生成，Token开销不能由文件后缀推断。此工具没有人工审阅时长数据，也未证明任一载体让创作更好。最终选择看本次任务与用户实际反馈，不拿导出速度替代工作流收益。
