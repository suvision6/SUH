# 回看、局部修订和交付

## 证据与归属

将实际媒体对应本次Prompt、采用来源和可读范围。文字只能检查设计，静帧能支持该时点可见状态，不能证明完整动态、口型或对白次数；真实音视频也只证明其实际覆盖范围。不可见不等于正确，未读取不等于缺失。

先定位偏差：采用方向自身冲突、Prompt遗漏/歧义或容量规划、素材映射/真实输入、模型执行，或者证据不足。缺原输入时不要强归因模型。最新错图/漏词音轨不成为后段事实；不能一边承接实际错尾帧一边宣称保持相反初态。候选与采用分开，用户实际接受的范围才更新有效依据。

修目标及直接依赖，如后段初态、持物、对白预算、光声延续、相关素材职责。无关内容不顺便润色。比对目标是否修正和旧正确内容是否退化；语义、审美和媒体检查不被机械PASS代替。重复同策略无改善时重新诊断，不无限叠词、不自动换戏或批量重试生成。

## 归因与交付的专业边界

实际回读、修订、新旧比较和同源派生按[Workflow步骤6—8](Workflow.md#6-先读实际会演出的过程再核对来源与承接)执行。本文件处理证据如何支持结论及载体能力，不重复完整检查流程。

版本或实传输入未对齐时保留该缺口，不能凭成片猜用图。静帧只支持该时点可见状态，声音未实听不能报告发言次数；没有真实媒体，只能报告文本设计检查和具体待验证项。文本相同、语义正确、静态布局合理和动态剪辑成立是不同结论。

归因落在实际层次：有效设计冲突回对应职责；已采用动作在正文遗漏或歧义则修表达；素材标签错则修输入关联；正文与素材矛盾先消冲突；相同明确条件仍执行错则保留不确定性和下一验证对象，不宣称模型必能修好。失败尾帧只有用户明确接受对应新设定时才更新项目事实。

### 专项偏差怎么修

有实际反馈才按需定位，不给普通任务新增逐项验收。表演的触发、听者反应、过度动作与跨场重置按[表演延续与局修](Performance-continuity.md#反馈落到哪一处表现)处理，以下表格用于合成与视觉线索：

| 所述/实读问题 | 核对与针对性修改 |
|---|---|
| 新物像贴片、太锐、边缘发白 | 对齐所在时点和深度，核对母版清晰度/焦点、颗粒、运动模糊、大气与边缘；按[合成分支](Assets-and-tasks.md#实拍合成先定母版与可改维度)只改不匹配的维度，保护其他已成功光线/颜色，不用全片模糊掩盖 |
| 相机动时物体滑动、换景后悬空 | 需要实际连续运动证据；恢复承载面、固定锚点、相机/主体运动与遮挡视差关系。单帧只支持该时点，不据此断言全段绑定正确；不为修绑定改掉原运镜 |
| 材质或动物质感不对 | 先区分形态、运动和表面问题。适用时用真实已读参考只修纹理/材质，不带入其光线、背景或姿态；没有参考就按已知特性改写并保留未知，不机械再加“更真实” |
| 关键字读错、过早看清或大小漂移 | 对照实际采用字面、出现位置与观看时点；检查映射/正文及同空间尺度锚。改某一次出现不全局替换，移焦不自动增Cut，不用放大实物或删掉文字替代原叙事；改变揭示/后期处理属于具体取舍 |

只收到文字反馈就注明“用户描述”，不写成自己已观看的结果。诊断后给目标段完整新版正文，并比较未修改部分；相关接点或输入职责一起更新，其余单元保持。若源片没有所需动作锚，可提出真实首帧驱动的新生成等备选，说明会失去哪些源动作/运镜约束；不自动切换、添加空镜拼接或付费重试。

## 交付方式

交付采用正文外说明与可复制正文两层；必要素材占位映射交由用户最后手动映射/@，不把上传/绑定设为文本门禁。多段按需用 [Prompt-master.md](../templates/Prompt-master.md)，其中来源、范围、接续、设置和未验证事项都是正文外的说明，不强制所有任务填写空表。当前采用内容只有一份主稿，JSON/TXT/MD不各自重写。旧版本并列；旧归档不因新校验规则被追认语义正确。

实际文件交付至少能取得每段完整正文和次序，不以“请把这些规则自行组合”代替成品。需要来源/对白结构核对时选[统一交付工具](Delivery-tool.md)；它的覆盖检查针对Agent录入的单元，支持全句及同一次发言跨单位的原字片段复组，不倒逼长台词或生成边界改变。已有完整正文纯保存时用下方工具，两种工具的检查能力不同。

本轮审阅载体先比较、不锁默认；Prompt正文遵循[Output-format](Output-format.md)。多段的MD主稿可同源派生Excel或固定HTML审阅样稿；TXT仅为复制附件，不代替人类可审阅的完整成果。`review_delivery.py`从同一Bundle渲染载体及提取返还差异，完整用法和批注兼容范围见[同源载体比较与反馈](Review-delivery.md)。保存的浏览器反馈/返回工作簿才是可读回的数据，不能把尚未导出的页面临时编辑当作已收到；按稳定ID核对实际修改，再回有效主稿，不让Agent分别重写两个版本。人类阅读是工作链的必要环节，不替代专业内容与Agent调度。

使用状态记录的文件工作，导出且回读后按[调度状态](Workflow-state.md)登记实际Bundle与直接依赖。若用户返还意见改变了有效源，先按[Active-context.md](Active-context.md)判断失效范围，修实际正文及真实接点，然后另存新版本；不得只修改Excel显示而让下游仍读旧Bundle。

### 同文导出工具

可选 `scripts/save_prompts.py` 使用Python标准库，只导出已写好的正文。它不解析剧本、不规划段落、不验证源覆盖/对白/摄影/时间容量、不联网、不执行媒体。

输入是Agent从工作稿派生的轻量JSON，不是用户必填表：

```json
{"format":"suh-prompt-bundle/1","units":[{"id":"G01","prompt_text":"这里是已完成的完整正文。"}]}
```

`id`用于文件名，只接受首字母为英文字母、其后英数字/短横/下划线，最长64；大小写冲突、Windows保留名及已有输出目录会被拒绝。其他字段原样保留在Bundle.json。可用字段写来源、接续、操作或估时，但脚本不审这些字段含义，不能凭导出通过认证它们。

```text
python3 <skill-root>/scripts/save_prompts.py --input <工作稿.json> --output <未存在的新目录>
python3 <skill-root>/scripts/save_prompts.py --input <旧prompt-plan.json> --output <未存在的新目录> --legacy
```

第二条仅显式读取 `su-prompt-plan/2.2` 的已写正文，保留原格式和元数据，不将旧镜头稿转换成新场级结构；旧源镜/场次/对白校验需独立回读，不由本工具重做或冒称兼容验证。其他旧格式不猜测。

输出 `Bundle.json`、`Prompts.md`、每段TXT及 `Integrity.json`；TXT正文与输入逐字一致，MD是展示载体，不作为重新解析主稿。报告只证明输入快照及已导出的字节一致，语义和媒体均为未验证。输出中途遇I/O失败可能留下部分文件；不自动删除，报告错误后使用新的明确路径或用户处理残留，不能覆盖重跑。
