# Prompt正文格式与Cut计划时间

本文件是本Skill正式生成Prompt的唯一格式与时间规范。结构沿用指定 `su-promptskill 2.2.2-candidate` 的表达基础；删除未采用素材区、全Cut默认计划时间和默认无字幕是本次用户定制，不是Seedance官方通用强制要求。载体选择不改变这份正文规范。

## 适用边界

有分镜输入的生成Prompt，包括场级采用稿和精确采用稿，使用下述结构及每个实际Cut的连续起止计划时间；单Cut也写。任务叫“测试”或“快速验证”本身不构成豁免。只有用户明确要求不用时间戳时，才省略Cut起止范围；仍保留Cut编号，以及符合本次入口profile的整数秒段总长。

无分镜独立入口保留授权内的导演与摄影能力；正式生成沿用下述区块，【镜头脚本】可用自然段，不虚构源镜号。用户明确时长是创作条件；未要求估时、未给总长的非提交草稿不强造时间表。提交总长同样遵守整数秒及本次入口profile。编辑与延长按[素材与任务](Assets-and-tasks.md)保留唯一母版、实际时间线和新增边界，不套普通生成格式。

当前入口约束的唯一数值来源是[Generation-profile.json](Generation-profile.json)：依据本轮用户明确指定，每个提交生成单元总长为4—30秒（含端点）的整数秒。整数约束仅作用于提交视频整段duration；内部切换点及每个Cut自身时长（包括最后Cut）均可为小数。这里不推断“CS”的含义，也不把该范围当作所有provider的事实。以后切换入口时，先核对实际入口并使用对应profile；其他文档及检查器引用同一份数值，不能各自写死上限。

## 正文顺序与内容

`【生成目标】→按需【参考素材职责】→【主体、关系与场景】→【镜头脚本】→按需【声音与台词】→【保持一致】`

| 区块 | 写什么 |
|---|---|
| 【生成目标】 | 本生成段主体、地点及核心过程，不抄全剧摘要。 |
| 【参考素材职责】 | 只写本段必要素材；逐主体、群体、道具或场景分别映射，每行一个实体及其参考用途。 |
| 【主体、关系与场景】 | 必要身份与关系、固定空间、当前初态；前段已完成动作成为状态，不重演，不预写本段终态。 |
| 【镜头脚本】 | 按实际观看切换写Cut，写清摄影、完整动作、同步或先后、原词发言、动作终态与切点。首次相关动作前，必要当前初态须可由【主体、关系与场景】或对应镜头读清；换Cut只补本镜新增或变化的依据，不强制首句四项模板，也不因此新增静止停留或重启动作。写法见[生成可执行性](Generation-executability.md)。 |
| 【声音与台词】 | 按需补声线、声位、环境/动作音效与跨Cut声桥，不复抄台词或重演动作。 |
| 【保持一致】 | 只保留身份、数量、服装、固定空间等真正不变量，不锁住应发生的移动、交接或情绪变化。 |

没有内容的可选区块省略，不输出【未采用素材】或项目库存。必要参考可保留如 `⟦林遥身份参考⟧` 的用途占位符，由用户最后手动映射/@；已明确标签原样保留。占位不代表已看图、上传或绑定；无法读取时不补造外观、音色或内容，读取缺口写在正文外。多素材共同定义同一实体时分别说明补充属性，不生成多个副本。

对白在实际发生的Cut就地写 `角色（声位，已知语言）说：{原文}`；语言未知不猜方言或口音。原字词、标点、说者、声位、次数和顺序保留，跨Cut发言只写本Cut实际播放的原字片段，按序复组一次。最终正文不用D3或 `[dialogue:D03]` 代指台词；可选导出器的内部标记必须先展开再交付。声音段只补声音关系，不能成为第二遍口播。详见[对白计时](speech-and-dialogue.md)。

每个完整Prompt默认在末尾简洁声明一次“画面不生成字幕，字幕后期添加”；用户明确要求生成字幕时按本次要求。无字幕不删除对白、配音、环境音或信纸、门牌等剧情文字道具。内部【】标签是指令结构，不是画面字幕。

## 先定整段，再分配实际Cut

1. 先读内容与时间条件：独立短文已给明确时长，就在该条件内设计观看、动作展开与切留，并核实发言、先后/同期和必要阅读能容纳；承接已有分镜则先保留给出的动作时间与声画关系。开放预算按可读取音轨/实读、项目校准、明确的计划假设依次估算，不伪造过程数值迁就希望总长，不从旧附件搬通用容量。
2. 采用用户已给的合规整数总长；未给时选有内容依据、符合profile的整数秒，再按实际Cut工作量分配。过程估算可含小数或区间，提交总长不可。超上限或不足下限时只调整合法生成组织或明确开放的动作/观看，并回写正文；不只改元数据，不平均切时间、无脑填满、删锁定对白或强提速。保留既有镜头、剧情、原词及硬时点；与明确时长或profile仍冲突时，保留原稿并指出具体条件和最小取舍，其余独立范围继续。
3. 每段从0起，各Cut正时长、相邻接续、无空缺或重叠，最后终点等于该段整数秒总长。例如 `Cut 1｜0—3.5秒`、`Cut 2｜3.5—11秒`，最后Cut自身为7.5秒，合法。单镜同样写 `Cut 1｜0—11秒`；内部小数按实际估算保留，不要求任何Cut凑成整数。覆盖整段只是计划算术一致性，不是物理精准切点；不得把末Cut设为凑整专用余量。已有实际镜头及切点默认继承，生成请求分组不重剪；段落、分镜行、Beat、Image9格或时间格均不自动对应Cut。
4. 写完正文后实际演读并回核：每Cut是否容纳自身发言、动作、必要停顿和结果可读时间；任何占时抵扣是否在正文明确同期。跨Cut持续声音不重播，后Cut不替前Cut“预说”原话。依据演读调整开放预算或合法分段，保留采用的因果、摄影锁定与硬时点。

这是一份可解释的计划，不是模型实际切镜、发言或帧级准确的保证。用户已有硬时点仍保留在对应Cut，并明确实际起算处；与合理预算或profile冲突时定位冲突，保留完整原话和受锁设计。当前profile的用户约束须遵守；尚未实测的入口能力仍标“容量未核实”，不能借此忽略已有profile，也不能把满足数值范围报成能力通过。语义关系确实未定、无法排出合理计划的范围如实标待定，其余完整段继续。

整数秒计划总时长、估算依据、适用profile及容量状态放正文外；Cut起止范围和叙事触发写在正文内。画幅、分辨率、帧率、接口请求时长仍属外层设置，构图影响落实到正文。内部过程估算与最终计划有差额时，落实到有依据的动作或观看过程并回核，不能仅改请求参数掩盖正文仍是旧总长。

## 交付与核对边界

外层简记实际范围/采用依据、必要素材映射、计划总长及实质未知；内层为上述可独立复制正文，不混入来源hash、长审计、解释标题或代码围栏。Markdown、Excel及固定HTML只是同一正文的审阅载体，载体默认尚未选定不表示Prompt正文格式尚未确定。

先按[Workflow的正文演读](Workflow.md#6-先读实际会演出的过程再核对来源与承接)核对内容，再按需做[确定性检查](Delivery-tool.md)。机器数据由Agent从实际来源、采用范围与最终正文提取，用户无需填表；工具只能查已声明事实和可机械验证的结构，不认证艺术、语义、实际采用或媒体表现。
